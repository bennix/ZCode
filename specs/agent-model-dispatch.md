# Agent 模型调度

## 产品规则

- 设置页提供独立的“总调度模型”选择，并提供自动调度开关。关闭时沿用用户在会话中选定的执行模型。
- 调度模型在新任务已由 Core 准入、但主执行模型首次创建前判断任务复杂度、可用执行模型与推理档位。运行中输入、短回复和任务续接沿用当前任务的执行选择；用户显式指定执行模型时以用户选择为准。
- 当前产品的一条任务由一个会话承载；只有会话的首个普通用户轮次可发起自动调度判断。续接即使文字很长也沿用上一轮实际执行模型，不以字符数猜测“新任务”，避免半途切模与重复判断开销。用户要开始独立任务时创建新会话；手动切模仍按本次用户选择执行。
- 调度选择是本次执行约束，不改写 Session Selection、默认模型或子 Agent 配置。用户应能看到本轮实际执行模型。
- 不同执行模型共享同一个会话级 `messageHistory` 与已有 compact summary；这些内容包含任务目标、用户约束、已完成操作和工具结果。接手模型在下一次请求前读取同一份已提交历史。长会话需要交接摘要时沿用已有 compact 路径，不另建第二份可写上下文真相。它不等同于供应商的 prompt cache，也不能声称缓存跨模型复用。
- 续接优先沿用上一条实际 assistant 响应的模型与推理档位。档位作为运行时历史元数据和已存在的持久 assistant info 字段保存，不送入 provider 对话正文；冷恢复必须重建同一选择。若目录不再支持该档位，则仅退回该模型当前默认档位，不伪造旧选项。
- 调度模型与执行模型分别配置；调度模型自身必须在当前连接中可用，且不能因为它给出一个模型名就绕过模型目录、鉴权和能力校验。
- 带图片、PDF、文件或 URL 附件的输入如果判断器只收到文字，不得根据残缺任务描述自动切模；沿用提交选择并省去本次判断请求。附件仍按原执行链交给主模型，后续若增加可验证的附件摘要需先更新本规则。
- 判断提示词的模型候选列表有上限时，必须优先保留本轮提交模型与调度模型；活目录顺序或模型数量不能让合法任务完全失去调度判断。其余候选按目录顺序有界选取。调度模型若不适合作为执行模型，仍可通过判断器返回 `keep`。
- 判断协议在送到提供商的最后一条用户消息中也要完整说明“只评估任务、不执行任务、仅返回 JSON”，并把任务正文标为不可信数据。部分兼容 Chat Completions 的网关不遵循独立 system 消息；无法取得合法 JSON 时保守回退原模型，同时保留判断用量。
- 判断请求用稳定的本次候选序号传递模型，并允许短 JSON 序号答复，以减少重复的 provider/model 字符串；Core 必须把序号映射回这次受控候选列表，再按活目录、档位与缓存安全规则验收。序号越界、非整数或非法档位一律回退，不能把模型文本当可执行配置。保留旧完整模型名答复解析兼容既有适配器与测试。
- 不假定跨供应商的价格、缓存和 effort 语义相同。没有可信元数据时保留当前推理档位；不做无依据的节省费用承诺。
- 同一执行模型的推理档位调整只在活模型目录明确给出 `effortChangePreservesCache` 时生效。当前唯一可推导的正例是直连官方 Anthropic Messages API 的 Claude Opus/Sonnet；第三方网关、Fable 与未知模型不自动调整同模型档位。Bootstrap 从当前 Provider Registry 的 API 类型和官方端点生成该只读事实，Core 仅按目录事实验收，不按模型名自行猜测。切到不同模型时可选择其目录支持的档位，因为切模本身已跨缓存边界。
- Token 效益按“调度请求 + 执行请求 + 因切模失去的缓存命中”合计评估，而不是只比较执行模型的单价。相同任务的短续接不反复调用调度模型；长历史继续使用现有 compact 机制压缩发送内容。设置页不能承诺固定节省比例。
- 用户提供的小规模编排实验说明规划、交接和重复读上下文可能比直接执行更贵；该实验只有 9 个文件、每组 2 轮，不构成自动分工阈值。当前模型调度只选择本轮执行模型，不自动生成子 Agent。若将来加入自动多 Agent 分工，必须先以完整任务成本（规划者、判断器、子 Agent、缓存及供应商额外调用）和真实环境验收建立收益门禁；规格已经能逐处写出改动的小任务默认由单一执行者完成。
- 费用报告使用运行请求中实际解析的 provider/model ID 和请求用量。模型别名、另一个终端里的 CLI 版本或供应商未报告的后台 advisor 消耗都不能作为精确账单依据；未观测到的费用明确标为未知。静态门禁和模型复核之外，涉及路径、原生应用或部署的任务仍需在对应真实环境验证，不能把“代码检查通过”写成“可运行”。
- 现有任务用量 `totalTokens` 扣除同一来源重复上下文前缀，是上下文增量口径，不能当作 API 请求总用量。任务用量接口另返回逐请求报告的输入/输出合计及其中 `model_dispatch` 的合计，并保留所有请求的 cache read/write Token；这些值由 usage ledger 的 `model_usage` 行汇总，不另建可写用量状态。字段称为“请求用量”，不能当作实际货币账单；比较开启与关闭调度的两次完整任务时，应分别使用请求用量和 cache read/write 数据，并注明供应商计价差异。
- 调度判断只需返回短 JSON；Core 对判断请求设置不超过 128 Token 且不超过活模型目录上限的输出预算，防止独立判断器无界生成。预算只约束该辅助调用，不改变主执行模型的输出额度；若供应商无法在预算内给出合法 JSON，沿用提交模型。
- 设置页只指定调度模型、不指定档位时，Core 用活目录列出的第一个（最低）推理档位运行该次判断；没有档位则保持模型默认。判断器的档位不写入会话 Selection 或执行模型，且判断失败仍按原提交选择回退。
- 共享上下文预览根据现有快照给出有条件的提示：上下文窗口占用达到 80% 时提示可压缩或交接；只有主请求已有至少两次缓存命中统计、最近输入达到 2000 Token 且最新命中率低于 10% 时，才提示最近一次缓存命中低。缺少统计时不猜测缓存状态，提示不自动切模、开新会话或压缩。

## 所有者与边界

- `ISettingService` 是自动调度开关与调度模型选择的唯一持久化所有者。UI 通过 `useSettings` 读写，并通过现有模型目录展示可用项。
- CLI/Core 的 `CommandInbox` 是已接受输入的唯一队列；调度判断不建立第二条 accepted 队列。`inputId` 仍是幂等键。
- CLI/Core 会话运行时的 `messageHistory` 是共享上下文的唯一所有者，compact summary 仍按现有事件持久化和恢复。UI 只能查看已提交内容，不能把草稿写为已验证事实；切模不创建另一份历史或异步摘要写入路径。
- 会话界面提供“共享上下文”只读预览，展示快照窗口内最近的已提交用户输入、上下文 Token 水位及可见的 compact 成功标记，并明确窗口可能省略较早内容。Core 的完整 `messageHistory` 和内部 compact summary 不直接投影到该区域；区域不能声称显示完整目标、约束或摘要正文。用户若要修正内容，应以普通会话输入提交并进入现有事件历史；该区域不维护第二份隐藏状态。
- 最近输入列表使用语义列表展示正文，不显示内部 rowId；在 320px 移动宽度及较长翻译文本下，列表与汇总行不横向溢出，也不遮住主输入操作。
- 调度判断仅生成一次性 `modelSelection` 与 `modelExecution.selectionScope = "execution"`，沿现有 v4 command、Host 和 Core admission 传递。不能调用 `setModel` 或 `setThoughtLevel` 来实施自动选择。
- 首次任务与续接的判定必须读取会话权威状态；Renderer 的草稿与 optimistic overlay 不是任务状态真相。

```text
用户提交 → 设置快照 + v4 sendText → Core CommandInbox admission
                                      ↓
                     模型目录 + 会话历史 → 调度判断 → 本轮执行模型
                                                     ↓
                                      已提交事件 → 同一 messageHistory
```

Desktop 的 continuous 与手机 Web 的 replayable 只投影同一个 Core 结果，不分别调度；远程 workspace 在其所属 Host 上使用同一规则。判断返回晚于状态修订时丢弃结果并按原选择发送；不得把 stale 判断用于后续输入。

交接上下文沿用现有上下文窗口预算、compact 和原始会话事件。摘要不能覆盖原始事件；模型需要细节时仍可读取原始内容。摘要生成失败时沿用常规历史，不阻断任务。切换只能发生在受控请求边界，不能打断正在进行的工具调用或丢失工具结果。

## 失败与迁移

- 配置缺失、调度模型不可用、判断失败、输出不合法时，新任务保留提交时的用户模型；同任务续接沿用上次实际执行模型。上次模型已从活目录移除或本次创建失败时退回提交模型。发送不得因调度失败而丢失。
- 旧设置没有调度字段时自动调度关闭，无需迁移或重写已有会话。
- 用量响应新增的逐请求字段在 wire schema 中可缺省，以兼容旧 Host；缺省表示该 Host 没有逐请求口径，不能解释为零。新 Host 对空会话显式返回零，对已有 `model_usage` 行按查询时计算，无需数据库迁移或回写历史。
- 开启调度前，设置页必须说明何时生效以及失败回退；不能显示已启用但实际执行链未接入的控件。
- 已开启调度后，若所选判断模型从当前目录消失或配置为空，设置页要提示当前不可用，并允许用户直接关闭开关；未开启且没有可用判断模型时仍禁止开启。失效配置只由 `ISettingService` 持久化，UI 不自行改写设置。

## 验收场景

1. 设置页可选择独立调度模型并持久化；重启后保持选择。
   1a. 已开启调度的判断模型失效时，开关仍可关闭并持久化；未配置可用判断模型时不能开启。
2. 开启后，新任务仅在模型可用且判断合法时按一次性选择执行；会话默认模型不变。
3. 运行中的引导输入、排队续接、用户手动切换模型均不被重新调度。
   3a. 同一会话第二轮的长文本续接不再调用判断模型，也不切换上轮实际执行模型；从存储恢复的会话遵守相同规则。
4. 无可用调度模型、网络失败、非法输出和目录变化时按原模型执行，且不重复发送。
   4a. 模型目录超过候选上限且当前模型排在末尾时，判断器仍收到当前模型与调度模型，合法选择才生效。
   4b. 带附件且只有短文字说明的输入不调用判断模型，主模型仍收到附件并沿用提交选择。
5. Desktop 与手机 Web 对同一任务显示相同的实际执行模型；远程 workspace 不使用本机错误的模型目录。
6. 从模型 A 切到模型 B 时，B 读取同一会话的已提交历史和 compact summary；A 的未提交草稿不会进入 B 的上下文，也不会因为切模新建会话。
   6a. B 以低推理档位完成一轮后，继续输入与重启冷恢复均沿用 B 的实际档位；目录移除该档位时安全回退。
   6b. 同模型 Opus/Sonnet 在官方直连 API 下可按判断结果调整合法档位；第三方代理、Fable 和未知缓存语义的模型保持当前档位。无档位或无变化时不重建模型句柄。
7. 统计调度模型与执行模型各自的输入/输出 Token，并比较开启与关闭调度的完整任务成本；不能把判断器消耗漏算。
   7a. 同一会话中主请求的重复上下文前缀仍按旧 `totalTokens` 增量口径汇总；新增逐请求总量必须保留每次主请求，并将调度判断请求计入总量和单独的小计。没有调度请求时小计为零。供应商 `totalTokens` 缺失时按该行归一化输入与输出求和，cache breakdown 不重复叠加。
8. 共享上下文预览在 Desktop 与手机 Web 从同一快照重建，显示最近已提交用户输入、可见的 compact 标记及窗口截断提示；不泄露内部摘要正文。
9. 使用本地受控模型端口完成一条真实 Core turn：判断模型返回合法切换后，执行模型收到当前任务和同一会话已提交历史，最终 `ModelRequest` 与回复标识实际执行模型，Session Selection 保持用户提交值。该测试不代替真实提供商的成本与缓存对照。
10. 真实提供商对照使用两个全新 Core 会话、相同系统提示与相同合成代码任务，一次关闭调度、一次开启调度；联网验收须显式选择并使用已有环境凭据，默认测试不发付费请求。报告每个实际请求的模型、输入/输出/缓存 Token、提供商报告的费用及总和，并把调度请求单列。任务必须真正完成，若判断器未切到低成本模型或任一请求失败，记录事实而不声称节省。该受控对照只证明所选任务与本次供应商计价，不能外推固定节省率或跨模型缓存复用。
   请求归因以发起调用时的请求内容与对应 Core `ModelRequest` 为准，不能用网络完成顺序推断；标题生成等并发辅助请求也必须计入总量。HTTP 成功但没有可用文本、HTTP 错误及提供商返回的失败用量同样保留在报告中，不能从成本分母消失。
   10a. 压缩判断提示词前后各跑一次同条件对照；检查判断请求输入/输出、总请求 Token、实际模型与费用。若只是费用下降而总 Token 增加，验收记录必须分别写出，不能将两种口径混为一谈。
