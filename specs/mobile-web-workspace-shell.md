# 手机 Web 工作区主区域

## 产品规则

- 普通 Web 首次在窄屏打开工作区时，任务输入与创作、工作区入口必须位于可视视口内。项目侧栏初始收起；顶部现有侧栏按钮仍可打开它。主区域须为顶部按钮保留空间，按钮不能压住创作或多 Agent 标题。
- 宽屏 Web 与 Desktop 保持原有侧栏默认状态和分屏尺寸。窄屏 Web 打开侧栏时，侧栏覆盖在主区域上方，不挤压主区域；关闭后主输入立即恢复可操作。
- 从宽屏 Web 缩至窄屏时收起侧栏一次；用户在窄屏主动打开侧栏后，不因普通 React 重渲染再次收起。切回宽屏不强行替用户打开侧栏。
- 手机 Web 的引导面板高度须给顶部侧栏按钮、常驻输入框及底部操作留出空间；内容超出时在引导面板内滚动，首行标题不可从视口顶部溢出。多 Agent 的任务输入和开始按钮应在首次打开时完整露出；窄屏可压缩卡片内边距和任务输入最小高度。
- 草稿页的装饰性问候和其顶部弹性留白在引导面板打开时让面板从屏幕中部向下增长；窄屏 Web 此时隐藏问候并取消该留白，让创作生成按钮在首次展开时位于视口内。关闭引导面板后恢复问候和原居中布局。该呈现由现有引导面板 DOM 派生，不引入第二份状态。
- 普通 Web 不显示用于操作当前设备的电脑控制插件开关；浏览器控制开关仍按插件状态显示。Desktop 的 Windows、macOS、Linux 可显示电脑控制开关。能力由 Desktop 平台注入的明确标记提供，不能把 Web 的占位命令函数当成原生执行能力。Linux Desktop 的输入栏 CUA 入口与 Windows/macOS 遵守同一平台门。
- Desktop 的远程 workspace 不显示本机电脑控制开关，包括存在 `remoteSessionId` 或远程 `workspaceIdentity` 的场景；浏览器控制开关仍按该 workspace 的插件状态显示。切换回本地 workspace 后重新显示本机开关，开关本身不另存状态。

## 所有者与时序

- `useAppPanels` 是侧栏显隐的唯一状态所有者，初始宽度和跨断点事件只更新它已有的 `isSidebarVisible`。`WorkspaceShellLayout` 只投影窄屏覆盖布局，不保存第二份显隐状态。
- Web `matchMedia` 进入窄屏 → 原显隐状态收起 → 主区占满视口；用户点击现有按钮 → 同一显隐状态打开覆盖侧栏；再次点击 → 收起。Desktop 不走这条窄屏逻辑。
- 不改变任务、会话、草稿、Host 或远控状态；侧栏节点保持挂载以保留局部导航状态。
- Desktop 平台对象是 `isDesktopRuntime` 的唯一来源；Web 平台对象明确为 false。输入栏仅据此投影按钮，不另存平台状态。

## 验收

1. 隔离数据的真实手机 Web 页面在 320px 首次进入工作区时，主输入和创作/工作区入口完整位于视口内，不被侧栏裁掉。
2. 打开侧栏可查看项目，关闭后主输入恢复；侧栏打开期间主区尺寸不缩小。
3. 宽屏 Web 和 Desktop 仍按原默认状态显示侧栏；宽屏 Web 缩至窄屏时收起一次。
4. 创作和多 Agent 引导面板在该真实手机 Web 工作区中均可打开，主操作可见，不发生水平溢出。
5. Linux/macOS/Windows 的普通 Web 均无本机电脑开关；Desktop 三平台有该开关。Linux Desktop 的 CUA 输入入口可以挂载，普通 Web 不能因占位函数而误入。
6. Desktop 远程 workspace 的电脑开关不可见，浏览器开关仍可见；本地 workspace 可见电脑开关，且两者都只读取插件概览而不复制开关状态。
