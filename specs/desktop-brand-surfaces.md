# ZenCode 桌面品牌入口

## 产品规则

- 首次启动欢迎页、初始化等待页、入门引导、主窗口顶栏、收起侧栏和新任务问候统一展示 ZenCode 蓝底章鱼应用图标；品牌文案为 ZenCode，不出现旧的 `worker` 标记或 Z 字母。
- ZenMux 作为 API 提供方名称和选择器图标保留，其图标只出现在明确标注 ZenMux 的提供方控件里，不能充当应用 Logo。
- `ZenCodeAppLogo` 是 UI 品牌图标的单一入口，各页面只设置尺寸和动画。图像内容与桌面主图一致，见 `specs/zencode-brand-icon.md`。
- 深浅主题中图标保持可见，欢迎页移动宽度下不压住标题与操作。
- Web 登录页、强制升级窗口、桌面系统菜单及电脑控制提示等面向用户的产品名称统一为 `ZenCode`。协议标识、环境变量、旧数据目录与内部错误码继续使用原标识，确保兼容。
- macOS、Windows、Linux 的 About 窗口标题和中英版权行均使用 `ZenCode`；“版权所有 © 年份 ZCode”是漏改的旧产品文案。年份来源保持现有规则，只改产品名。About 的更新检查状态由现有 updater 所有，不因品牌文字修正重新触发检查。
- 内置技能在 UI 中显示的中英描述若提到应用、内置浏览器或插件，也使用 `ZenCode`。技能 id、插件目录、来源判定和原始 manifest 不改；只调整官方内置技能的展示描述，不重写第三方技能内容。
- 强制升级窗口在 renderer 尚不可用时由 Desktop Main 生成；优先读取安装包内蓝章鱼图标，图标缺失时以产品名文字占位，不回退成单独的 `Z` 字母。
- macOS 电脑控制 Helper 的安装、验签、权限身份和拖拽预检查失败时，返回给界面的错误正文使用 `ZenCode Computer Use`；原有 fail-closed 判定、Helper bundle 身份、权限状态和返回结构保持单一所有者及原顺序。内部协议键、旧目录和文件名保持兼容。
- 会话订阅在 Agent runtime 反复回收且重连额度耗尽时，连接错误提示使用 `ZenCode` 名称，并继续显示手动“重新连接”入口。`ConversationProjectionStore` 是本地订阅状态的唯一所有者；只更新展示错误，不改重试次数、时序或内部兼容匹配字符串。

## 所有者与边界

- `packages/ui` 的品牌组件拥有应用 Logo 画法。欢迎页和各 Shell 入口只读取该组件，不保存品牌状态或调用平台服务。
- 登录提供方图标继续由现有提供方 UI 负责；更换应用品牌不改动账户选择和凭据。
- Web 登录页文案由 Web auth locale 表拥有；强制升级窗口文案由 Desktop Main 的升级提示拥有。两者只消费固定品牌名称，不另存品牌状态。

## 验收

1. 新数据目录首次启动时，欢迎页头部可见蓝底章鱼图标和 ZenCode 名称，不含 `worker` 或 Z 字母；ZenMux API Key 选择器仍显示 ZenMux。
2. 等待、引导、Windows 顶栏、桌面叠层、侧栏收起和新任务问候入口均使用同一蓝底章鱼图标。
3. 深色和浅色主题、窄屏时品牌标志不与标题或按钮重叠。
4. 中英两种语言的 Web 登录页、强制升级窗口、Windows 控制提示与系统菜单均显示 `ZenCode`；强制升级窗口图标资源缺失时也不显示单字母 `Z`。
5. macOS 电脑控制授权入口与拖拽预检查在不支持平台及 Helper 安装失败时返回的错误正文均显示 `ZenCode Computer Use`；失败仍拒绝继续授权。
6. About 中英文版权行都显示 `ZenCode`，不显示 `ZCode`；从最终安装包打开 About 验证品牌图标、产品名和版权行一致。
7. 官方内置浏览器、插件创建和 Browser Use 的技能描述显示 ZenCode；第三方技能描述原样保留。
8. 连续四次 runtime unavailable 后，订阅状态为 error，`lastError` 含 ZenCode 而不含旧产品名；手动重试仍复位退避计数。
