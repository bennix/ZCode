# 引导式工程流程

固定来源 addyosmani/agent-skills@39b723ceebf81474d0557c1fecd01eddab585563，版本 0.6.16，MIT。当前上游包含 25 个技能和 9 个 Markdown 生命周期命令。

以独立内置插件 `knowledge-engineering` 接入，与 11 个专业领域共用「专业工作」向导，默认关闭。选择工程领域后显示六个阶段：需求、规划、实现、测试、审查、发布；每个阶段展示所需输入与预期证据。允许已有项目从适合的阶段进入，不把点击步骤视为完成证明。另提供 meta-skill 自动选择，只加载适用技能。

技能、Markdown commands、agents 和共用 references 一并打包，避免单独复制 skills 导致共享检查表丢失。命令采用插件 namespace，不覆盖宿主 /plan、/review。不安装上游会话 hooks，避免每次启动全量注入；新增简短 ZenCode 适配说明，插件命令内部引用改成自身 namespace；persona model 前置字段移除，沿用用户选择及 ZenMux 成本档位，不硬绑 Claude 型号。

阶段选择只生成可编辑对话草稿，执行仍由原有 Agent admission、权限与用户授权控制。需求产出 spec；规划记录依赖/验收；实现小步修改；测试记录真实命令和结果；审查记录具体发现与修复；发布先给出检查结果、目标、回滚和监控方案，未获任务授权不得实际发布。缺前置材料时先检查仓库或询问，不虚构测试通过。

单一状态所有者仍为原专业向导（草稿）和 CLI runtime（执行事实）；不会新建并行会话或以 UI checkbox 维护发布成功状态。DevTools 只在浏览器分析任务中按需启用；不能因为工程插件开启就自动启动 Chrome。检查结果沿用既有探针/工具事件。

验收：25 技能/9 commands/共享 references/许可打包完整；六阶段提示与技能路径匹配；meta 可选；发布草稿含证据与授权边界；窄屏无溢出；既有 11 专业领域行为不变。
