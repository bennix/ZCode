## 验收原则

2026-10-10：`ZENCODE_IDE_TEST_ROOT=/tmp/zencode-ide-two-instance-check pnpm exec tsx --test packages/desktop/tests/code-workbench-theme.test.mjs` 的 4 项均通过，其中新增两个同时运行的真实内置 IDE 实例分别接收主题流，验证 A 浅/B 深与 A 深/B 浅。该证据提升了运行时隔离覆盖，但仍不是两个 Electron 窗口的打包应用验收。

2026-10-10：Windows/Linux 打包 workflow 已加入各架构 unpacked 应用的首次电脑控制设置 E2E。该 E2E 在 macOS arm64 Preview 包以默认语言和 `--lang=en-US` 均通过，验证开关初始关闭、手动启用以及设置页和插件页同步；Windows/Linux 工作流尚未推送执行，不能据此声称其打包应用通过。

2026-10-10：Core 自动调度已取消同一会话续接的“超过 80 字再次判断”路径。定向单测与完整 Core turn 测试共 7 项通过；首轮仍由判断器选 strong，短、长两次续接均由 strong 执行而没有第二次判断请求。这减少了可证明的重复判断请求次数，但尚无真实提供商的开启/关闭完整任务成本对照。

- Windows 原生动作须用登录的交互桌面与预置二进制执行；MCP 握手不算 GUI 动作通过。
- Linux GNOME portal 须在有真实 portal 与权限提示的 Wayland 桌面测试；Weston AT-SPI 成功不代表 portal 成功。
- Token 对照要使用两次完整任务的 `requestTotalTokens`、`dispatchRequestTokens`、`requestCacheReadTokens`、`requestCacheCreationTokens`，并记录实际执行模型及供应商计价口径；旧 `totalTokens` 是上下文增量，不用于净成本结论。
- 打包 App 的窗口布局和首次启用需要真实安装包验收；组件浏览器与独立 IDE 运行时测试不能代替。
- 2026-10-10 `pnpm --dir packages/desktop build:no-runtime-assets` 成功，Electron 经 CDP 捕获了当前源码首页与创作面板。该启动不是正式安装包，而且 `ZCODE_HOME` 与桌面 userData 覆盖没有完全隔离 `ZCODE_DATA_BASE_DIR`，读取到了本机既有任务；已停止测试进程。后续桌面运行验收须同时设置隔离的 `ZCODE_DATA_BASE_DIR`，不能沿用此次启动作为首次安装证据。
